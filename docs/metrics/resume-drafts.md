## 1. CAE：基于现有实现的文字稿

项目：CAE 仿真任务调度与结果管理平台  
角色：Java 后端开发（按本人实际职责填写）  
技术栈：Java、Spring Boot、MySQL、Redis、RabbitMQ、Python、Vue、NFS、Docker。

项目简介：面向科室共用算力下任务提交分散、执行状态难追踪及结果整理重复的问题，建设统一任务控制、输入校验与结果/报告编排流程。结构工况为主要闭环，其余专业按实际接入深度描述。

- **任务调度：** 负责统一提交接口、批量编排与资源预占，按 CPU、内存和 License 约束分批派发，串联提交、执行与结果流程。
- **执行可靠性：** 拆分 Job/Execution，结合 Outbox、消费幂等与执行对账，处理消息重投、回调丢失和后端重启后的状态恢复。
- **输入治理：** 协同制定 Case Package 规范，负责 INCLUDE 依赖校验与输入快照，将缺失依赖和输入版本问题前置到执行前。
- **结果与报告：** 负责结果/报告元数据、版本追溯和阶段重试编排，联调 Python 后处理，支持复用求解结果生成标准报告草稿。

边界：上述技术机制可据当前公开实现解释；个人主写范围按本人实际工作确认。公开仓库为后续 Mock 复现，不能当作历史企业交付证据；Python 专业脚本、商业求解内核和前端页面不归为本人全部开发。

## 2. CAE：优秀性能目标版，全部未实测

本节只供项目设计与未来压测验收，不是投递版已取得成果。每条目标需携带协议、样本数及环境。

- **任务调度：** 负责统一提交、批量编排与资源预占，按 CPU/内存/License 约束分批派发；**目标：50-Case 批次受理 P95≤300 ms**。
- **执行可靠性：** 拆分 Job/Execution，结合 Outbox、消费幂等与执行对账；**目标：500 次重放新增进程为 0，30 轮故障恢复后状态收敛 P95≤15 s**。
- **输入治理：** 负责 INCLUDE 预检、输入快照与校验反馈；**目标：120 组回归样本正确拦截 40 组非法输入，80 组合规样本误拦为 0**。
- **结果与报告：** 负责结果/报告元数据与阶段重试，联调 Python 后处理；**情景假设目标：标准报告人工整理中位耗时 60→15 min，减少 75%**。

补充性能目标：同一合成数据集下，20 并发 Job 详情 P95≤120 ms，20 并发 Job 创建 P95≤400 ms。两项都未实测，不与“50 个 Case 求解完成”混为同一指标。

范围解释：
- 批次受理以父批次和全部 intent item 持久提交为准，不表示全部子 Job 已校验、启动或完成。
- 500 次为重复请求数，另有 20 次原始请求，总共 520 请求；目标 20 个原始外部启动，重放不新增。
- 15 秒从恢复条件就绪起算；30 轮限三个已定义场景，不能改写成任意故障恢复或全年可用性。
- 40/40 与 0/80 是有限样本目标，不能改写成生产提交失败率为零。
- 60 分钟人工基线也是假设；30 组配对测量尚未开展。报告收益为团队链路共同成果，突出个人的后端编排、可追溯和重试设计。

## 3. Arclight：基于已有材料的文字稿

项目：Arclight 终端智能编程 Agent  
角色：个人项目（按本人实际开发范围确认）  
技术栈：Python、asyncio、Pydantic、MCP、Skills、Textual、上下文管理。

项目简介：面向代码理解、需求实现与修复任务构建终端编程助手，串联模型调用、代码检索、编辑和测试，并通过上下文管理与会话持久化支持长任务。

- **执行闭环：** 实现多轮 Agent Loop，统一模型流式事件与工具参数校验，串联代码检索、文件编辑、测试及错误回注。
- **上下文管理：** 对大输出落盘、历史裁剪与分层摘要，保留近期原文及文件/Skill 快照，恢复后续执行所需上下文。
- **工具与协作：** 统一 MCP 工具 Schema，按需发现并加载工具；通过角色隔离、后台任务和 Mailbox 组织独立探索。
- **验证与恢复：** 支持 worktree、会话记录和状态恢复，按固定任务集比较修复结果、完整用量及完成耗时。

本节不把当前未经完整轨迹核实的 31.57%、23.1%、32.16% 或 SWE-bench 结果改写为确定业绩。当前目录属于 CAE 项目，只提供简历编辑附录，不表示 Arclight 代码在本次修改。

## 4. Arclight：优秀效果目标版，全部未实测

- **任务效果目标：** 固定模型与预算，在 SWE-bench Lite 300 上解决率≥60%，即至少 180/300；逐题保留补丁、轨迹和官方 F2P/P2P 结果。
- **长上下文目标：** 60 组同任务对照，完整输入 Token 减少≥35%，计入主/子代理、摘要及重试调用，并保持任务质量。
- **工具加载目标：** 固定同一组 50 个外部 MCP 工具，首请求输入 Token 相对全量加载减少≥70%，同时验证工具发现可用。
- **并行探索目标：** 30 组独立探索任务，完成耗时中位配对比下降≥25%，完整 Token 开销增幅≤25%，以相同完成质量为约束。

目标版精简展示写法，仍须保留目标标签：
- **上下文与扩展：** 实现大输出落盘、分层摘要和 MCP 按需加载；**目标：长会话完整输入 Token 减少≥35%，50 工具配置首请求 Token 减少≥70%**。
- **任务协作：** 基于独立上下文、后台任务和 Mailbox 并行探索；**目标：30 组任务耗时下降≥25%，完整 Token 增幅≤25%**。
- **评测设计：** 采用固定模型与预算比较基础 ReAct 和完整框架；**目标：SWE-bench Lite 300 解决率≥60%（180/300）**。

任务集、对照结果和上述优秀效果均尚未产生。Token 的输入、输出、缓存和价格分别记录；预算相同指上限及配置相同，不强制两方案实际消耗一致。
