# Milestone 5 validation

The final gate passed 163 Java tests, 36 Python tests, Spotless/Ruff/ESLint, frontend type checks/build and the backend Docker build. The rebuilt backend applied V4 and started healthy with a real RabbitMQ submission listener.

`OutboxIntegrationTest` verifies Job/journal/event-and-command Outbox atomic commit/rollback, concurrent SKIP LOCKED claims, expired-owner fencing, and an actual broker-confirmed but unroutable mandatory publication remaining RETRY rather than SENT. `InboxIntegrationTest` verifies ten concurrent physical deliveries acquire one logical handling lease, DONE remains stable, stale owners are fenced, and exhaustion callbacks/Job/events roll back with Inbox failure transactions. `SubmitMessagingIntegrationTest` uses actual RabbitMQ with owned Outbox IDs to verify duplicate allocation/dispatch, durable concurrent-message deferral, ACK while a controlled remote solver remains running, bounded retries and real DLQ with one retained UNKNOWN attempt/reservation. The shared isolated schema is never globally published by these tests.

The first gate found a real MySQL deadlock: concurrent duplicate INSERT IGNORE operations acquired shared unique-row locks before all requesting FOR UPDATE. A no-op `ON DUPLICATE KEY UPDATE id=id` now takes the exclusive row lock directly while preserving the existing claim. The full suite passed after this change.

The live [messaging smoke evidence](m5-messaging-smoke.json) uses actual independent Worker processes. Eight concurrent duplicate API submissions produced one execution/process. The command's Inbox completed in 1.15 seconds in this local run, and actual broker ACK counters advanced while the Solver was RUNNING. A four-second first-response delay exceeded the backend's two-second HTTP timeout; a new physical delivery reused the same logical event, stored execution request hash, request ID, external ID and process identity. A targeted invalid-version message was rejected into `cae.job.submit.dlq`; its x-death header confirmed the source queue and rejection reason, and its payload remained available without changing business executions.

The smoke confirms its own completed Solver outcomes via the cancellation API to release only its own reservations. These Jobs remain POST_PROCESSING until M6/M7 install reconciliation and parsing. This milestone claims transport and idempotent acceptance, not a completed result/report pipeline.

Two real isolation checks created, published, read/requeued and removed a probe in an owned Rabbit vhost; owned MySQL schema/grants and Redis keys were also removed, with demo DB/queue counts unchanged. Docker vfs build space recovered by removing a verified unused public Maven extraction image; workspace Java/Maven and every runtime container/image/volume remained intact.
